# Обработка сообщений о неточности

Цель процесса — исправлять данные ЦеноВеда, не обещая действия от имени магазина.

## Что сохраняется

- предложение и магазин через `offerId`;
- причина: цена отличается, нет в наличии, другой товар или другая структурированная неточность;
- цена, увиденная пользователем, только для расхождения цены;
- серверный снимок показанной цены и времени наблюдения предложения;
- время создания и статус `OPEN`, `RESOLVED` или `DISMISSED`.

Контактные данные, IP, имя, свободный текст и пользовательский идентификатор не собираются. Повторная отправка одного клиентского UUID не создаёт дубликат.

## Правила разбора

1. Сверить `offerId`, идентичность комплектации и время исходного наблюдения.
2. Проверить следующий разрешённый фид или документированный API магазина. Не обходить ограничения сайта и не считать пользовательское сообщение доказательством само по себе.
3. Если расхождение подтверждено, пометить предложение недоступным/устаревшим либо исправить источник импорта; не редактировать цену вручную без наблюдаемого источника.
4. Закрыть обращение как `RESOLVED` с краткой внутренней причиной либо `DISMISSED`, если расхождение не подтверждено.
5. Не обещать пользователю доставку, возврат, гарантию или компенсацию от имени продавца.

До публичного запуска нужен операторский экран для этой очереди и защита от массового спама. В текущем пилоте записи доступны только через PostgreSQL и не отправляют внешних уведомлений.
