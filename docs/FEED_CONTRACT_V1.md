# Контракт CSV фида v1

Контракт предназначен для согласованного локального импорта предложений ноутбуков одного магазина. Файл передаётся вне приложения; публичной формы загрузки нет. Импорт не скачивает страницы и не переходит по ссылкам из CSV.

## Формат

- UTF-8, допустим BOM; разделитель — запятая.
- Первая строка должна в точности совпадать с заголовком контракта.
- Поля с запятыми, кавычками или переводами строк заключаются в двойные кавычки; кавычка внутри поля удваивается.
- Максимум 5 МиБ и 50 000 строк данных.
- MPN и GTIN читаются как строки: ведущие нули сохраняются.

Порядок колонок:

```text
merchant_id,merchant_offer_id,category,brand,manufacturer_part_number,gtin,model,variant,price_rub,currency,in_stock,product_url,observed_at
```

Все поля обязательны, кроме `gtin`; для отсутствующего GTIN оставляется пустое поле.

| Поле | Правило v1 |
|---|---|
| `merchant_id` | Идентификатор из серверного `config/merchants.json` |
| `merchant_offer_id` | Стабильный уникальный ID предложения у магазина |
| `category` | Только `laptops` |
| `brand` | Бренд производителя, не магазина |
| `manufacturer_part_number` | Точный MPN производителя |
| `gtin` | Необязательный GTIN-8/12/13/14 с корректной контрольной цифрой |
| `model` | Человекочитаемое название; не используется как ключ matching |
| `variant` | JSON-объект с `screen_inches`, `ram_gb`, `storage_gb`, `region` |
| `price_rub` | Положительное целое число рублей; цена, доступная обычному покупателю |
| `currency` | Только `RUB` |
| `in_stock` | Строго `true` или `false` |
| `product_url` | HTTPS без логина/пароля, hostname должен быть разрешён для магазина |
| `observed_at` | ISO 8601 с `Z` или явным смещением часового пояса |

Синтетический пример лежит в `fixtures/merchant-feed-v1.csv`. Он не содержит коммерческих данных.

## Matching и очередь проверки

Автосопоставление возможно, только если категория, бренд и вариант совместимы, а затем выполняется одно из правил:

1. один каталоговый товар имеет тот же валидный GTIN;
2. один каталоговый товар имеет тот же нормализованный brand + MPN.

В обоих случаях должны совпасть диагональ, RAM, SSD и регион. Конфликт GTIN, неправильный вариант, несколько кандидатов или отсутствие точного идентификатора дают статус `REVIEW`. Похожее название никогда не объединяет товары автоматически.

Оператор может просмотреть очередь через `pnpm matches:review -- list` и проверить конкретную запись через `pnpm matches:review -- inspect <identity-id>`. Инспекция не изменяет базу: она показывает только каталоговые товары с тем же GTIN либо нормализованным brand + MPN и отдельно сообщает, совместим ли вариант. Для разрешения нужно исправить проверенный master-каталог и получить следующий разрешённый фид; назначение по похожему названию запрещено.

## Полный и инкрементальный фид

- `full`: отсутствовавшие в новом полном файле предложения этого магазина остаются в журнале, но получают `active=false`, `stale=true`; связанное предложение становится недоступным.
- `incremental`: отсутствие строки ничего не меняет.
- Наблюдение старше 24 часов относительно времени получения файла получает `stale=true` в обоих режимах.

Только доступные, неустаревшие предложения из фида участвуют в дневном минимуме. Реальная история хранится с источником `MERCHANT_FEED` отдельно от `DEMO`; дни без наблюдений не заполняются.

## Что нужно от реального магазина

До подключения нужны: письменное разрешение использовать фид и ссылки, стабильный `merchant_offer_id`, точные MPN/GTIN и вариант, определение `in_stock`, правила цены (без персональных промокодов), допустимые домены, частота обновления и признак полного либо инкрементального файла.
