# Проверенное состояние — 2026-09-12

## Факты

- Каталог содержит 18 детерминированных демонстрационных товаров: 9 ноутбуков и 9 телевизоров. Цены, наличие, отзывы и 90-дневная история сгенерированы.
- UI реализован на Next.js App Router, TypeScript и Tailwind; есть поиск, фильтры, карточки, страницы товара, сравнение и защищённый redirect.
- В обычном Next.js есть путь Prisma/PostgreSQL при `DATA_SOURCE=postgres`. В режиме по умолчанию и в Sites используется память с demo seed.
- Drizzle/D1 присутствует как пустой шаблон и каталог приложением не обслуживает.
- Git настроен: локальная ветка `main` связана с приватным `origin` `https://github.com/CHarlyChimp/cenoved.git`. Текущая доработка ведётся в ветке `codex/price-report`.
- CSV importer v1, миграция, dry-run, точный matching, очередь review, политика full/incremental и разделение demo/real history реализованы.
- Для фактических предложений реализовано сообщение о неточности: строгий API, идемпотентный UUID запроса, снимок показанной цены и времени предложения, очередь `PriceReport` без контактных данных. В demo форма не показывается и запись не имитируется. Оператор может просматривать и закрывать очередь через `pnpm reports:manage`.
- Реального магазина, фида или подтверждённых каталоговых MPN/GTIN в проекте пока нет. Конфигурация `synthetic-shop` и обе фикстуры явно тестовые.

## Препятствия до первого реального сравнения

1. Получить разрешённый фид и договориться о смысле цены, наличия, времени наблюдения и полном/инкрементальном режиме.
2. Создать небольшой проверенный master-каталог точных ноутбучных SKU с MPN/GTIN и регионом; текущий demo seed таких подтверждённых идентификаторов не содержит.
3. Применить миграции и дважды прогнать импорт на PostgreSQL. Docker/PostgreSQL в текущей среде отсутствуют, поэтому транзакция и rollback пока проверены только статически.
4. Добавить операторский интерфейс для разбора matching-очереди `REVIEW`; для `PriceReport` уже есть консольный процесс, но перед публичным запуском потребуется аутентифицированный интерфейс или отдельная операторская среда.
5. Согласовать SLA обновления; порог 24 часа сейчас является гипотезой.

## Следующий шаг

Получить один обезличенный пример CSV от потенциального магазина вместе с разрешённым доменом и описанием полей. До записи прогнать его через `--dry-run`, измерить доли rejected/matched/review и вручную проверить каждый auto-match.
