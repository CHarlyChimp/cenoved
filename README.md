# ЦеноВед

Рабочий MVP агрегатора цен: две категории, фильтры, карточки, предложения магазинов, история цен и сравнение моделей. Интерфейс на русском, адаптирован для телефона и компьютера.

**Все коммерческие данные демонстрационные.** 18 товаров (9 ноутбуков и 9 телевизоров), 3–6 предложений на товар, 90 ежедневных точек истории, 2–4 вымышленных отзыва. Фотографии показывают серии устройств: конкретные комплектации в seed не подтверждены производителем. Ни один магазин пока не подключён.

## Два режима запуска

| Режим | Приложение | Данные |
|---|---|---|
| Локальный, без базы | Next.js App Router + TypeScript + Tailwind | Детерминированный seed в памяти |
| Локальный, с базой | Тот же Next.js + Prisma 6.19 | PostgreSQL, миграции и seed |
| Приватная демоверсия Sites | Совместимый с App Router Vinext / Cloudflare Worker | Тот же seed в памяти |

В размещённой демоверсии PostgreSQL не подключён. `vite.config.ts` подменяет только модуль источника данных на `lib/demo-repository.ts`. Обычный Next.js использует `lib/repository.ts` и обращается к настоящей базе при `DATA_SOURCE=postgres`. Ошибка подключения в этом режиме отображается как ошибка: приложение не подменяет её моковыми данными.

## Быстрый старт без PostgreSQL

Нужны Node.js 22.13+ (подойдёт Node.js 24) и pnpm, версия указана в `package.json`. Команды выполняются из папки проекта в Ubuntu/WSL, macOS или терминале Windows. В Windows команду `cp` можно заменить на `copy`.

```bash
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
pnpm db:generate
pnpm dev:next
```

Откройте `http://localhost:3000`. В `.env` по умолчанию стоит `DATA_SOURCE=demo`; база для просмотра интерфейса не нужна. Остановка — `Ctrl+C`.

В системах без Corepack установите версию pnpm из поля `packageManager` в `package.json` через npm. Не меняйте менеджер пакетов и не удаляйте lockfile.

## Запуск с PostgreSQL

Дополнительно нужен Docker с Docker Compose либо установленный PostgreSQL. Для Docker задайте свой локальный пароль в **обоих** значениях `POSTGRES_PASSWORD` и `DATABASE_URL` в `.env`.

```bash
docker compose up -d --wait
pnpm db:generate
pnpm db:migrate
pnpm db:seed
```

Теперь установите `DATA_SOURCE=postgres` в `.env` и запустите `pnpm dev:next`. Если сервер уже работал, перезапустите его. Проверить записи можно командой `pnpm exec prisma studio`.

`db:migrate` применяет сохранённую миграцию. Для новых изменений схемы в разработке используйте `pnpm exec prisma migrate dev --name meaningful_name`. Не используйте `db push` вместо истории миграций.

Seed выполняется транзакционно и повторно обновляет только фиксированные идентификаторы демонстрационных записей. Повторный запуск не создаёт дубликаты истории и отзывов. Не запускайте seed против боевой базы с реальными данными. Docker сохраняет данные в именованный том; `docker compose stop` останавливает сервер, сохраняя данные.

## Импорт CSV одного магазина

Реализован контракт CSV v1 для пилота ноутбуков. Он валидирует файл до записи, не открывает URL из фида и автоматически сопоставляет товар только по точному GTIN либо нормализованным brand + MPN при полном совпадении диагонали, RAM, SSD и региона. Название модели не участвует в автоматическом объединении. Полное описание: `docs/FEED_CONTRACT_V1.md`.

Проверить синтетический пример без базы:

```bash
pnpm feed:import -- --file fixtures/merchant-feed-v1.csv --mode full --dry-run --catalog fixtures/product-catalog-v1.json
```

Команда должна сообщить: одна принятая и сопоставленная строка, ноль отклонённых. Фикстура и магазин `synthetic-shop` тестовые — это не подключение реального продавца.

Для сохранения сначала примените миграции к PostgreSQL, добавьте разрешённый магазин и точные идентификаторы товаров, задайте `DATABASE_URL`, затем выполните без `--dry-run` и `--catalog`:

```bash
pnpm db:migrate
pnpm feed:import -- --file path/to/feed.csv --mode full
```

`full` помечает ранее виденные, но исчезнувшие предложения магазина недоступными и устаревшими. `incremental` меняет только строки текущего файла. Наблюдение старше 24 часов считается устаревшим; оно хранится для аудита, но не участвует в минимальной цене и переходе к магазину. Весь импорт одного файла выполняется одной транзакцией. Повтор файла с тем же SHA-256 не создаёт новые записи.

## Сборка и проверки

```bash
pnpm test
pnpm typecheck
pnpm build:next
pnpm start:next
```

`pnpm build` — отдельная сборка приватной демоверсии для Sites; для самостоятельного размещения Next.js используйте `build:next` / `start:next`.

Проверки покрывают целостность 90-дневной истории, сочетание фильтров, сортировку по доступным предложениям и ограничения сравнения. Результаты проверок конкретной поставки записаны в `docs/VALIDATION.md`.

## Что работает

- Главная с поиском по названию, бренду и значениям характеристик.
- `/category/noutbuki` и `/category/televizory`: цена, бренд, динамические атрибуты категории, наличие, сортировка. Фильтры применяются без перезагрузки. На телефоне открываются в боковой панели.
- `/product/[slug]`: галерея из двух фотографий серии, описание, спецификации, предложения, график Recharts за 30/60/90 дней и доступная текстовая таблица цен, демонстрационные отзывы.
- `/compare?ids=...`: 2–4 товара одной категории, подсветка различий, режим «Только различия». Выбор сохраняется на текущем устройстве в localStorage; ссылку на готовое сравнение можно скопировать.
- `/go/[id]`: проверка наличия, HTTPS и разрешённого домена магазина, затем redirect. URL из пользовательского ввода не используется. В режиме PostgreSQL записывается Click без IP-адресов и идентификаторов пользователя; ошибка счётчика не блокирует переход. В деморежиме клики не сохраняются.
- Для фактических предложений `MERCHANT_FEED` на странице товара показывается форма «Сообщить о неточности». Она принимает только структурированную причину и, при расхождении, увиденную цену; email, IP, имя и свободный текст не сохраняются. В деморежиме форма скрыта, а API честно отказывает вместо ложного подтверждения.
- SSR, заголовки страниц и описания, состояния загрузки, 404, ошибки и пустой поиск.

Демоссылки открывают **главную страницу** магазина. Это не партнёрские ссылки и не подтверждение цены у продавца. Доставка не включается в сортировку, поскольку её стоимость неизвестна.

## Ограничения MVP

Импорт CSV v1 и строгий matching engine реализованы локально, но проверены только на синтетической фикстуре и ещё не прогнаны с PostgreSQL в этой поставке. YML, загрузка по расписанию, API продавцов, интерфейс ручной проверки, авторизация, настоящие отзывы, уведомления, CPC-биллинг и аналитика посещений пока не реализованы. PostgreSQL-поиск на полном каталоге, OpenSearch, Redis и очереди пока не нужны: интерфейс фильтрует небольшой набор данных на клиенте. Это потребует серверной пагинации перед ростом каталога.

Цена хранится целым числом рублей; набор данных поддерживает только RUB. История отражает минимум среди доступных предложений за день, а не среднюю цену и не заявленную скидку продавца. Она не используется для автоматического обвинения магазинов в мошенничестве. Реальные наблюдения нельзя смешивать со сгенерированной историей.

Демоверсия закрыта от индексации через `robots` в `app/layout.tsx`. Перед публичным запуском с подтверждённым каталогом нужно настроить домен, canonical, sitemap и метаданные для реальных данных, затем снять `noindex`.

Источники фотографий и условия, которые удалось установить: `docs/image-sources.json` и `docs/gallery-sources.json`. Открытая лицензия на эти изображения не подтверждена; для коммерческого запуска получите разрешённые изображения от магазинов/производителей.

Начните с `docs/CODEX_NEXT_TASK.md`. Там конкретное следующее задание: импорт одного согласованного CSV, точное сопоставление модификаций и очередь ручной проверки неоднозначных записей.
